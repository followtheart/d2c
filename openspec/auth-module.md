# OpenSpec: 用户认证模块

## 概述
用户认证模块提供完整的用户身份验证功能，包括注册、登录、密码重置，支持邮箱验证和JWT令牌认证。

---

## 模块一：公共基础设施

### 1.1 用户数据模型

**功能描述：**
定义用户数据结构，提供数据库操作接口

**数据模型：**
```typescript
interface User {
  id: string;              // 用户唯一标识
  email: string;           // 邮箱（唯一）
  password: string;        // 加密后的密码
  emailVerified: boolean;  // 邮箱是否已验证
  verificationCode?: string; // 邮箱验证码
  verificationExpiry?: Date; // 验证码过期时间
  resetToken?: string;     // 密码重置令牌
  resetTokenExpiry?: Date; // 重置令牌过期时间
  createdAt: Date;         // 创建时间
  updatedAt: Date;         // 更新时间
}
```

**测试用例：**
- ✅ TC-INF-001: 创建用户对象，验证所有必填字段
- ✅ TC-INF-002: 验证邮箱唯一性约束
- ✅ TC-INF-003: 验证密码字段必须加密存储
- ❌ TC-INF-004: 创建缺少必填字段的对象，应抛出异常

**验收标准：**
- 数据模型包含所有必要字段
- 邮箱字段有唯一性约束
- 密码字段不允许明文存储

### 1.2 JWT工具类

**功能描述：**
提供JWT令牌的生成、验证和刷新功能

**接口定义：**
```typescript
interface JWTService {
  generateToken(userId: string, email: string): string;
  verifyToken(token: string): JWTPayload | null;
  refreshToken(oldToken: string): string;
}

interface JWTPayload {
  userId: string;
  email: string;
  iat: number;
  exp: number;
}
```

**测试用例：**
- ✅ TC-JWT-001: 生成JWT令牌，验证包含正确的userId和email
- ✅ TC-JWT-002: 验证有效的JWT令牌，返回正确的payload
- ✅ TC-JWT-003: 验证过期的JWT令牌，返回null
- ✅ TC-JWT-004: 验证篡改的JWT令牌，返回null
- ✅ TC-JWT-005: 刷新有效的JWT令牌，生成新令牌
- ❌ TC-JWT-006: 刷新过期的JWT令牌，应抛出异常

**验收标准：**
- JWT令牌包含userId、email、iat、exp字段
- 令牌有效期为24小时
- 使用HS256算法签名
- 验证失败返回null，不抛出异常

## 模块二：用户注册

### 2.1 用户信息验证

**功能描述：**
验证用户注册信息的合法性

**验证规则：**
- 邮箱：符合RFC 5322标准格式
- 密码：长度≥8位，包含大小写字母、数字、特殊字符
- 邮箱唯一性：数据库中不存在相同邮箱

**测试用例：**
- ✅ TC-REG-001: 有效邮箱和强密码，验证通过
- ✅ TC-REG-002: 无效邮箱格式，验证失败，返回错误信息
- ✅ TC-REG-003: 密码长度<8位，验证失败
- ✅ TC-REG-004: 密码缺少特殊字符，验证失败
- ✅ TC-REG-005: 邮箱已存在，验证失败
- ❌ TC-REG-006: 空邮箱或密码，验证失败

**验收标准：**
- 所有验证规则都得到执行
- 错误信息清晰明确
- 验证失败时返回具体的错误原因

---

### 2.2 注册流程

**功能描述：**
处理用户注册请求，创建用户账户并发送验证邮件

**业务流程：**
1. 验证用户输入（邮箱、密码）
2. 检查邮箱是否已注册
3. 加密密码（使用bcrypt）
4. 生成6位数字验证码
5. 创建用户记录（emailVerified=false）
6. 发送验证邮件
7. 返回注册成功响应

**测试用例：**
- ✅ TC-REG-010: 完整注册流程，用户创建成功，验证邮件已发送
- ✅ TC-REG-011: 注册后用户emailVerified为false
- ✅ TC-REG-012: 验证码为6位数字
- ✅ TC-REG-013: 验证码有效期为1小时
- ❌ TC-REG-014: 邮箱已存在，注册失败
- ❌ TC-REG-015: 邮件发送失败，注册回滚

**验收标准：**
- 用户数据正确保存到数据库
- 密码使用bcrypt加密
- 验证码已生成并发送到用户邮箱
- 返回用户ID和提示信息

---

### 2.3 邮箱验证

- ❌ TC-VERIFY-005: 过期的验证码，验证失败
- ❌ TC-VERIFY-006: 用户不存在，验证失败

**验收标准：**
- 验证码匹配且未过期时验证成功
- 验证成功后用户状态正确更新
- 验证失败返回明确的错误信息

## 模块三：用户登录

### 3.1 凭证验证

**功能描述：**
验证用户邮箱和密码

**业务流程：**
1. 接收邮箱和密码
2. 查找用户记录
3. 验证密码（使用bcrypt.compare）
4. 检查邮箱是否已验证
5. 返回验证结果

**测试用例：**
- ✅ TC-LOGIN-001: 正确的邮箱和密码，验证通过
- ✅ TC-LOGIN-002: 错误的密码，验证失败
- ✅ TC-LOGIN-003: 邮箱不存在，验证失败
- ❌ TC-LOGIN-004: 邮箱未验证，验证失败
- ❌ TC-LOGIN-005: 空邮箱或密码，验证失败

**验收标准：**
- 密码验证使用bcrypt.compare
- 邮箱未验证的用户不允许登录
- 验证失败不暴露具体原因（安全考虑）

---

### 3.2 JWT令牌生成与返回

**功能描述：**
登录成功后生成JWT令牌并返回

**业务流程：**
1. 凭证验证通过后，调用JWTService生成令牌
2. 返回令牌和用户基本信息

**测试用例：**
- ✅ TC-TOKEN-001: 登录成功，返回JWT令牌
- ✅ TC-TOKEN-002: 返回的用户信息包含id和email
- ✅ TC-TOKEN-003: 令牌有效期为24小时
- ✅ TC-TOKEN-004: 令牌包含正确的userId

**验收标准：**
- 登录成功返回JWT令牌
- 响应格式：{ token: string, user: { id, email } }
- 令牌有效期正确

---

### 3.3 令牌验证与刷新

**功能描述：**
验证JWT令牌有效性，支持刷新令牌

**测试用例：**
- ✅ TC-REFRESH-001: 有效令牌刷新成功
- ✅ TC-REFRESH-002: 刷新后生成新令牌
- ❌ TC-REFRESH-003: 过期令牌刷新失败
- ❌ TC-REFRESH-004: 无效令牌刷新失败

**验收标准：**
- 有效令牌可以刷新
- 刷新后旧令牌仍然有效（平滑过渡）
- 过期令牌不能刷新

## 模块四：密码重置

### 4.1 重置请求

**功能描述：**
处理密码重置请求，发送重置邮件

**业务流程：**
1. 接收邮箱地址
2. 查找用户记录
3. 生成重置令牌（UUID）
4. 设置令牌过期时间（1小时）
5. 发送重置邮件（包含重置链接）
6. 返回成功响应

**测试用例：**
- ✅ TC-RESET-001: 有效邮箱，重置请求成功
- ✅ TC-RESET-002: 重置令牌已生成并保存
- ✅ TC-RESET-003: 重置令牌有效期为1小时
- ✅ TC-RESET-004: 重置邮件已发送
- ✅ TC-RESET-005: 邮箱不存在，仍返回成功（安全考虑）
- ❌ TC-RESET-006: 无效邮箱格式，返回错误

**验收标准：**
- 重置令牌为UUID格式
- 令牌有效期为1小时
- 无论邮箱是否存在，都返回成功（防止邮箱枚举攻击）

---

### 4.2 密码更新

**功能描述：**
验证重置令牌并更新密码

**业务流程：**
1. 接收重置令牌和新密码
2. 查找匹配的用户记录
3. 验证令牌是否过期
4. 验证新密码强度
5. 加密新密码
6. 更新用户密码
7. 清除重置令牌和过期时间
8. 返回成功响应

**测试用例：**
- ✅ TC-RESET-010: 有效令牌和强密码，密码更新成功
- ✅ TC-RESET-011: 密码已加密存储
- ✅ TC-RESET-012: 重置成功后令牌被清除
- ❌ TC-RESET-013: 过期的令牌，更新失败
- ❌ TC-RESET-014: 无效的令牌，更新失败
- ❌ TC-RESET-015: 弱密码，更新失败
- ❌ TC-RESET-016: 令牌已使用过，更新失败

**验收标准：**
- 令牌有效且未过期时允许更新密码
- 新密码必须通过强度验证
- 更新成功后令牌被清除（一次性使用）

## 边界场景

### 并发场景
- 🔄 同一邮箱同时注册两次，只有一个成功
- 🔄 同一令牌并发重置密码，只有一个成功

### 异常场景
- ⚠️ 数据库连接失败，所有操作回滚
- ⚠️ 邮件服务不可用，注册流程回滚
- ⚠️ JWT密钥泄露，支持密钥轮换

### 安全场景
- 🔒 密码必须加密存储（bcrypt，cost factor ≥ 10）
- 🔒 JWT密钥长度 ≥ 256位
- 🔒 防止暴力破解：登录失败5次后锁定账户15分钟
- 🔒 防止令牌重放攻击：重置令牌一次性使用
